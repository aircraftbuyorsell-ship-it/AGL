## Result

**I-03 is IMPLEMENTED as a narrow `PROV-JSON-style` object converter, but it
does not consume the published PROV-JSON representation, does not preserve the
required PROV semantics, and is not conformant with the declared AGL
reconstruction contract.**

The adapter creates AGL node classes for declared PROV entities, activities and
agents, preserves their raw qualified names as external references, carries raw
attributes, and returns all required top-level AGL graph fields. Its synthetic
smoke test passes. The interoperability mapping conservatively labels W3C PROV
as `REFERENCE`, not `ADAPTER` or `CONFORMANT`.

The main boundary fails before deeper conformance can be assessed. Published
PROV-JSON relation members use names such as `prov:activity`, `prov:entity`,
`prov:agent`, `prov:generatedEntity` and `prov:usedEntity`. The implementation
looks only for unprefixed properties. An official-shape document therefore
produces nodes but zero edges and zero relation evidence. The committed fixture
uses non-standard unprefixed fields; even then, identifier prefix stripping
makes every relation endpoint unresolved, and generation swaps the entity and
activity types/direction.

## Official source baseline

The applicable W3C PROV family is stable and dated 30 April 2013. The audit
distinguishes normative Recommendations from supporting Notes and the separate
PROV-JSON Member Submission:

| Source | Status/version | Audit use |
|---|---|---|
| [PROV-DM](https://www.w3.org/TR/2013/REC-prov-dm-20130430/) | W3C Recommendation, 30 April 2013 | Authoritative conceptual model, types and relation semantics. |
| [PROV-O](https://www.w3.org/TR/2013/REC-prov-o-20130430/) | W3C Recommendation, 30 April 2013 | OWL2/RDF serialization of the model. |
| [PROV-N](https://www.w3.org/TR/2013/REC-prov-n-20130430/) | W3C Recommendation, 30 April 2013 | Human-readable notation used by the model and constraints. |
| [PROV-CONSTRAINTS](https://www.w3.org/TR/2013/REC-prov-constraints-20130430/) | W3C Recommendation, 30 April 2013 | Validity, typing, uniqueness and ordering constraints. |
| [PROV Overview](https://www.w3.org/TR/2013/NOTE-prov-overview-20130430/) | W3C Working Group Note, 30 April 2013 | Status and roadmap for the PROV family. |
| [PROV-JSON](https://www.w3.org/submissions/2013/SUBM-prov-json-20130424/) | **W3C Member Submission**, 24 April 2013; not a Recommendation and not endorsed by W3C | The actual JSON representation claimed by the repository mapping/adapter. |
| [W3C PROV repository](https://github.com/w3c/prov) | Official source repository | Specification history, ontology, examples and test cases. |

Normative/declared facts used in the audit:

- PROV-DM defines entities, activities, agents, usage, generation, derivation,
  attribution, association, delegation, bundles, alternate/specialization and
  collections. An activity uses an entity; an entity is generated by an
  activity; `actedOnBehalfOf` links delegate, responsible agent and optional
  activity context.
- Identifiers and attributes are qualified names. Namespace prefix expansion and
  co-reference handling precede PROV validation/equivalence checks.
- PROV-CONSTRAINTS makes entities and activities disjoint and constrains typing,
  uniqueness and event ordering, including generation before usage.
- A bundle is a named set of provenance descriptions and itself an entity,
  allowing provenance of provenance.
- PROV-JSON groups assertions by type and relation identifier, stores namespace
  declarations in `prefix`, and names PROV relation members with `prov:*` keys.
- PROV represents provenance and responsibility. It does not establish that an
  APL authorization decision preceded governed execution, and a PROV delegation
  relation is not by itself proof of authority attenuation.

## Gaps and blockers

- The exact PROV profile/serialization is not pinned; PROV-JSON is incorrectly
  easy to read as a W3C Recommendation although it is a Member Submission.
- Published PROV-JSON relation properties are not parsed, so the primary import
  path silently loses all relations and evidence.
- Qualified-name namespace context is discarded and private-field relations point
  to unresolved/collapsed identifiers.
- Generation semantics are reversed and mistyped even under the private fixture.
- Relation time, attributes, plan/role, delegation, bundles and most PROV-DM
  relation classes are not preserved.
- PROV-CONSTRAINTS validity is not checked or delegated to a declared validator.
- The adapter fabricates a completed epoch execution when no execution scope or
  ingestion timestamp is provided.
- No export/round-trip implementation exists despite the mapping target.
- CI validates the adapter only with a non-standard fixture and does not apply
  graph schema/referential/reconstruction checks to its output.
- No ABOS W3C PROV runtime exchange/evidence chain is attributable.
